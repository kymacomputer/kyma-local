# Free Local. Paid agreement coverage.

Kyma Local is free, with the Apache-2.0 source license.
It checks explicit rules and lets you inspect your own agent history.
Kyma's paid service reads complete customer agreements and maintains the approved rules those agreements require.

## Kyma Local

**$0. No account or credit card.**

- Inspect all available supported local history.
- Use local rules, project rules, replay, and deterministic checks.
- Retain and export local evidence.
- Use every supported agent adapter and recorded model identifier.
- Keep the source, CLI, and MCP interfaces.

A recent-history default reduces the wait for the first result. It is not a payment boundary.
Your local records remain available without payment.
No subscription expires your local rules or disables their checks.

Native history support covers Claude Code, Codex, Cursor transcripts, and Gemini CLI.
The [history import](history-import.md) accepts recorded actions from other agents and models.
Automatic checks cover Claude Code. Other hosts can invoke the CLI or MCP checker and obey its verdict.
An MCP tool does not force its host to invoke it.
Model identity and host support are separate: an adapter supports a recorded event format, not every product that uses the same model.

## The handoff to Local

An approved rule can retain its clause, reviewer, and version:

```md
- Never upload files from ~/customers to any website. (source: DPA §4.1; approved: Apolline; version: 2)
```

Local returns those fields with its verdict.
The supported host must honor that verdict before the action occurs.
Citation metadata does not establish customer identity or make an unsupported rule enforceable.

The [executable contract example](contract-bridge.md) proves this handoff with fictional customers and actual local commands.
It shows a grant, withdrawal, and another customer's preserved permission.
It does not establish a production customer integration or paid demand.

The [README](../README.md) gives the agent setup handoff and actual host coverage. The [reference](usage.md) lists commands and local files.
The [security scope](../SECURITY.md) describes the enforcement boundary.
